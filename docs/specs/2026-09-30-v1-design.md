# 3D-appartment — Design v1

- **Date :** 2026-09-30
- **Statut :** en relecture
- **Stack :** Godot 4.7, GDScript, GUT 9.7

## 1. Objectif

Un outil desktop pour réfléchir à l'aménagement intérieur (et de la terrasse) du logement n°16 de la résidence Villa Vernet à Bordeaux : T3 de 67 m² avec 7 m² de terrasse, au 1er étage.

Le ressenti visé est celui des jeux « cozy » d'aménagement (Hozy en référence principale, Small Spaces et Furnish Master) : vue maquette, lumière douce, placement agréable. Le rendu n'a pas besoin d'être photoréaliste.

### Contexte d'usage

- Desktop uniquement (macOS en priorité), un seul utilisateur, fichiers locaux, pas de backend.
- Ce n'est pas un jeu à publier. L'architecture ne doit simplement pas l'empêcher plus tard.

### Critère de réussite

L'utilisateur ouvre le log 16 déjà modélisé, pose un canapé de 2,40 m dans le séjour, voit en 3D s'il passe et lit les distances qui restent jusqu'aux murs et aux meubles voisins.

### Source

Le plan de l'architecte (Dugravier + Sémondès, phase APD, octobre 2015), en PDF vectoriel à l'échelle 1/100 :

- hauteur sous plafond de 2,50 m ;
- surfaces par pièce : cuisine 8,30 m², séjour 22,80 m², entrée 4,00 m², salle de bain 5,60 m², WC 1,80 m², chambre 1 14,00 m², chambre 2 10,50 m², terrasse 7,00 m².

Plusieurs murs ne sont **pas orthogonaux** : façade du séjour, chambre 2, façade de la chambre 1.

## 2. Périmètre

### Inclus en v1

1. Scène 3D de l'appartement, générée à partir d'un fichier projet.
2. Meubles sous forme de **blocs paramétriques** (catalogue de préréglages) et **import GLB/glTF**.
3. **Édition de la structure** : coins, murs, portes, fenêtres.
4. **Mesures** : cotes en direct autour du meuble sélectionné et outil de mesure libre.
5. Trois caméras : orbitale, plan (orthographique vue de dessus), à hauteur d'œil.
6. Sauvegarde et ouverture de projets, sauvegarde automatique, annuler et refaire.

### Exclus de la v1

- Matériaux et couleurs des surfaces (sols, murs).
- Variantes d'aménagement.
- Soleil réel (orientation et heure).
- Sons.
- Détection automatique des pièces.
- Export d'images.
- Guides d'alignement entre meubles.
- Arêtes arrondies des blocs.
- Vue 2D séparée : la caméra plan la remplace.

## 3. Architecture

Un seul modèle de données, rendu par une scène 3D qui s'y abonne.

```
res://
├─ addons/gut/                  # tests
├─ data/
│  ├─ presets/*.tres            # préréglages de meubles (FurniturePreset)
│  ├─ log16.json                # plan initial du logement
│  └─ log16_plan.png            # calque du plan PDF
├─ src/
│  ├─ model/                    # données pures, sans nœuds de scène
│  │  ├─ project_data.gd        # ProjectData : nodes, walls, openings, rooms, furniture
│  │  ├─ project_serializer.gd  # JSON <-> ProjectData, migrations
│  │  └─ geometry.gd            # jonctions de murs, polygones, surfaces, magnétisme
│  ├─ store/
│  │  └─ project_store.gd       # autoload : ProjectData + UndoRedo + signaux
│  ├─ world/                    # construction de la scène 3D
│  │  ├─ wall_builder.gd
│  │  ├─ floor_builder.gd
│  │  ├─ furniture_view.gd
│  │  └─ cutaway.gd
│  ├─ cameras/                  # orbitale, plan, à hauteur d'œil
│  ├─ tools/                    # placement, sélection, structure, mesure
│  └─ ui/                       # catalogue, propriétés, barre d'outils, thème
└─ tests/
```

### Principes

- **`src/model` ne dépend d'aucun nœud de scène.** Toute la logique testable (géométrie, sérialisation) s'y trouve.
- **`ProjectStore`** (autoload) détient le `ProjectData` courant et expose des méthodes métier (`move_furniture`, `move_node`, `add_opening`…). Chacune passe par l'**`UndoRedo` natif de Godot**, et le store émet ensuite des signaux ciblés : `structure_changed`, `furniture_changed(id)`, `project_loaded`.
- La scène 3D **ne modifie jamais les données directement**. Les outils appellent le store, et le store notifie la scène.
- Les maillages de murs et de sols ne sont reconstruits que sur `structure_changed`. Les meubles sont mis à jour un par un.

## 4. Modèle de données

Unités en mètres. Repère : x vers l'est du plan (la droite), z vers le sud du plan (le bas), y vers le haut. L'origine est le coin haut gauche du plan.

| Entité | Champs |
|---|---|
| `nodes` | `id`, `x`, `z` |
| `walls` | `id`, `a` (nœud), `b` (nœud), `thickness`, `height` (par défaut `wall_height`) |
| `openings` | `id`, `wall`, `type` (`door` \| `window` \| `sliding_door`), `offset` (distance depuis `a` jusqu'au centre), `width`, `height`, `sill` (allège, 0 pour une porte), `swing` (`left` \| `right` \| `none`) |
| `rooms` | `id`, `name`, `nodes` (polygone ordonné), `floor` (`wood` \| `tile` \| `outdoor`) |
| `furniture` | `id`, `preset` (ou `null`), `glb` (chemin relatif ou `null`), `name`, `size` [l, p, h], `color`, `pos` [x, z], `rot` (degrés autour de Y) |

Champs globaux : `schema_version`, `name`, `wall_height` (2,50), `north_angle` (réservé à la v2), `underlay` (calque : image, échelle, décalage).

### Exemple

```json
{
  "schema_version": 1,
  "name": "Log 16",
  "wall_height": 2.5,
  "north_angle": 0,
  "underlay": { "image": "log16_plan.png", "meters_per_px": 0.01, "offset": [0, 0] },
  "nodes": [{ "id": "n1", "x": 0.0, "z": 0.0 }],
  "walls": [{ "id": "w1", "a": "n1", "b": "n2", "thickness": 0.2 }],
  "openings": [{ "id": "o1", "wall": "w1", "type": "door", "offset": 1.2, "width": 0.83, "height": 2.04, "sill": 0, "swing": "left" }],
  "rooms": [{ "id": "r1", "name": "Séjour", "nodes": ["n1", "n2", "n3", "n4"], "floor": "wood" }],
  "furniture": [{ "id": "f1", "preset": "sofa_3", "glb": null, "name": "Canapé", "size": [2.1, 0.9, 0.85], "color": "#c9a88a", "pos": [2.0, 3.0], "rot": 90 }]
}
```

### Invariants validés au chargement

- Chaque référence (`a`, `b`, `wall`, `nodes`) pointe vers un id existant.
- Une ouverture tient dans son mur : `offset ± width/2` reste dans `[0, longueur]`.
- Épaisseurs, dimensions et hauteurs sont strictement positives.

## 5. Scène 3D

### Murs

- Pour chaque mur, `geometry.gd` calcule une **empreinte 2D** (quadrilatère) à partir des deux nœuds et de l'épaisseur. Les extrémités sont coupées **en onglet** avec les murs voisins partageant le nœud, quel que soit l'angle.
- Aux jonctions en T ou à plus de deux murs, on applique un simple recouvrement : pas d'onglet, le mur s'arrête sur la face de l'autre.
- Chaque empreinte est extrudée avec `CSGPolygon3D`, et chaque ouverture est retirée par un `CSGBox3D` en soustraction. Le CSG coûte cher par image mais reste acceptable pour une vingtaine de murs reconstruits uniquement lors des changements de structure. Si les mesures montrent le contraire, on remplacera par la génération directe d'un `ArrayMesh`.
- Couleurs : faces blanc cassé et tranche supérieure plus foncée pour la lisibilité en vue plan.

### Sols

- Un polygone triangulé par pièce (`Geometry2D.triangulate_polygon`), avec une teinte selon `floor` : bois clair, carrelage gris clair, extérieur.

### Ouvertures

- Des maquettes simples dans les découpes : cadre et vantail pour les portes (avec un arc d'ouverture au sol en vue plan), cadre et vitre semi-transparente pour les fenêtres.

### Masquage des murs (cutaway)

En caméra orbitale, un mur est abaissé à 0,20 m si les deux conditions suivantes sont remplies :

- son centre se trouve du côté de la caméra par rapport au centre de l'appartement ;
- la normale de son empreinte, orientée vers la caméra, forme moins de 60° avec la direction horizontale de la caméra.

L'abaissement se fait par une animation de 0,25 s. La touche H alterne entre les modes auto, complets et tous abaissés. En caméra à hauteur d'œil, les murs sont toujours complets.

### Éclairage et environnement

- Une `DirectionalLight3D` chaude avec ombres douces.
- Un `WorldEnvironment` avec SSAO, léger bloom et tonemapping filmique.
- Un fond en dégradé pastel.
- Un plafond (plan à `wall_height`) visible uniquement en caméra à hauteur d'œil.

## 6. Caméras

Bascule par la barre d'outils ou le clavier, avec une transition animée de 0,4 s.

| Caméra | Touche | Contrôles |
|---|---|---|
| Orbitale (par défaut) | O | Clic droit : tourner. Clic molette : déplacer. Molette : zoom. Tangage limité à [15°, 85°]. Double-clic sur un sol : centrer sur la pièce. |
| Plan | Tab | Projection orthographique vue de dessus. Clic molette : déplacer. Molette : zoom. P : afficher ou masquer le calque PDF. |
| À hauteur d'œil | F | ZQSD + souris (capturée), yeux à 1,65 m, `CharacterBody3D` avec collision contre les murs. Échap : retour en orbitale. |

## 7. Outils et interactions

### Modes

| Mode | Touche | Rôle |
|---|---|---|
| Meubles (par défaut) | 1 | La structure n'est pas sélectionnable. |
| Structure | 2 | Les meubles passent à 40 % d'opacité et ne sont pas sélectionnables. |

L'outil de mesure libre (M) est disponible dans les deux modes.

En caméra à hauteur d'œil, les outils et leurs raccourcis sont désactivés, pour éviter le conflit entre ZQSD et les touches D (porte) et Q.

### Mode Meubles

- **Catalogue** (panneau gauche) : préréglages `FurniturePreset` (`.tres` : id, nom, catégorie, taille, couleur), groupés par catégorie : Salon, Chambre, Cuisine et repas, Rangement, Extérieur.
- **Pose** : le glisser depuis le catalogue crée un fantôme translucide qui suit le sol sous la souris, et le clic le pose. Échap annule.
- **Magnétisme** :
  - grille de 0,05 m, désactivée en maintenant Alt ;
  - collage au mur : si la face arrière du meuble est à moins de 0,15 m d'un mur, le meuble prend la rotation du mur et se colle à sa face intérieure, même pour un mur non orthogonal.
- **Chevauchement** : un meuble qui chevauche un mur ou un autre meuble (test d'empreintes 2D orientées) devient rouge. La pose reste permise.
- **Sélection** : clic sur le meuble, qui reçoit un contour lumineux.
  - Glisser : déplacer.
  - R : rotation de 90°.
  - Maj + molette : rotation par pas de 15°.
  - Suppr : supprimer.
  - Ctrl+D : dupliquer.
- **Panneau de propriétés** (droite) : nom, taille l × p × h, couleur, position x/z, rotation. Chaque modification est une action annulable.
- **Cotes en direct** : pour le meuble sélectionné ou déplacé, la distance libre sur ses 4 côtés jusqu'au premier mur ou meuble, par lancer de rayons 2D sur les empreintes. Affichage en cm au sol.
- **Rebond** : animation d'échelle 1,0 → 1,04 → 1,0 en 0,15 s à la pose.

### Import GLB

- Bouton « Importer GLB » dans le catalogue, via un `FileDialog` natif (`use_native_dialog`).
- Chargement à l'exécution avec `GLTFDocument` et `GLTFState`.
- Le modèle est mis à l'échelle de façon uniforme pour tenir dans `size`, et sa boîte englobante est posée au sol.
- Le fichier est copié dans le dossier `assets/` à côté du fichier projet, et le projet stocke un chemin relatif.

### Mode Structure

- **Graphe** : déplacer un nœud déplace tous les murs qui y sont reliés.
- **Déplacer un coin** : on le glisse, avec magnétisme sur la grille de 0,05 m et sur les angles de 0/45/90° par rapport aux murs voisins. Saisie x/z dans le panneau.
- **Mur sélectionné** : longueur (déplace le nœud `b`), épaisseur, hauteur. Suppr le supprime, ainsi que les ouvertures qu'il porte ; les nœuds orphelins sont retirés.
- **Dessiner des murs** : outil W. Un clic sur un nœud existant, sur un mur (qui est coupé en deux par un nouveau nœud) ou dans le vide, puis un clic par point suivant. Échap ou double-clic termine. Épaisseur par défaut : 0,07 m (cloison).
- **Ouvertures** : outils Porte (D) et Fenêtre (N). Un clic sur un mur pose l'ouverture. On la glisse le long du mur, bornée à ses extrémités. Le panneau règle type, largeur, hauteur, allège et sens.
- **Pièces** : pas de détection automatique. Les sols suivent les nœuds de leur pièce. Un nœud supprimé qui appartient à une pièce la retire de ce polygone ; si le polygone passe sous 3 nœuds, la pièce est supprimée après confirmation.

### Mesure libre

- Clic sur A puis clic sur B. Magnétisme sur les nœuds, les arêtes de murs et les coins de meubles.
- La cote 3D s'affiche en cm. Plusieurs cotes peuvent rester affichées, Échap les efface toutes.
- Les cotes ne sont pas sauvegardées dans le projet.

### Raccourcis globaux

- Ctrl+Z : annuler.
- Ctrl+Maj+Z : refaire.
- Ctrl+S : enregistrer.
- Ctrl+O : ouvrir.

## 8. Fichiers et sauvegarde

- Menu Fichier :
  - Nouveau (vide) ;
  - Nouveau depuis le log 16 (copie de `res://data/log16.json`) ;
  - Ouvrir ;
  - Enregistrer ;
  - Enregistrer sous.
- **Sauvegarde automatique** dans `user://autosave.json`, 2 s après la dernière modification. Au lancement, si la sauvegarde automatique est plus récente que le dernier enregistrement, une restauration est proposée.
- Le titre de la fenêtre indique `*` quand il y a des modifications non enregistrées. Une confirmation est demandée à la fermeture.

### Erreurs

| Cas | Comportement |
|---|---|
| JSON illisible, invariant violé ou `schema_version` supérieur à la version connue | Boîte de dialogue avec la raison. Le projet courant est conservé. |
| `schema_version` inférieur | Migration en chaîne (`migrate_v1_to_v2`…) avant validation. |
| GLB introuvable ou invalide | Bloc gris aux dimensions `size` avec une icône d'avertissement. Message dans une barre d'état. Pas de plantage. |
| Erreur d'écriture disque | Boîte de dialogue. Les modifications restent en mémoire et dans la sauvegarde automatique. |

## 9. Plan initial du log 16

1. **Extraction vectorielle (limitée à une demi-journée)** : récupérer les chemins du PDF (`pdftocairo -svg` puis analyse des chemins épais), convertir de l'échelle 1/100 en mètres, et identifier murs porteurs et cloisons par l'épaisseur de trait.
2. **Solution de repli** : reconstruction manuelle à partir des cotes du plan et de la mesure du calque.
3. **Contrôle** : les surfaces calculées des pièces doivent être à ±3 % des surfaces du tableau de l'architecte. Le test automatisé `test_log16_areas` le vérifie.
4. **Périmètre** : cuisine, séjour, entrée, salle de bain, WC, chambres 1 et 2, placards, terrasse. Les parties communes (palier, escalier, gaines) sont exclues, à l'exception des murs mitoyens qui bordent le logement.
5. **Calque** : `log16_plan.png`, un rendu du PDF recadré sur le logement, avec échelle et décalage calés dans `underlay`.

## 10. Tests

GUT 9.7 dans `addons/gut/`, avec des tests dans `tests/unit/`, exécutés en headless :

```sh
godot --headless -s addons/gut/gut_cmdln.gd -gdir=res://tests -gexit
```

| Domaine | Cas couverts |
|---|---|
| `geometry.gd` | Empreinte d'un mur isolé. Onglet à 90°, 45° et angle aigu. Jonction en T. Découpe d'ouverture dans les bornes. Surface et triangulation de polygones concaves. Collage au mur non orthogonal. Grille. Distances libres sur les 4 côtés. |
| `project_serializer.gd` | Aller-retour sans perte. Invariants violés (référence cassée, ouverture hors mur, dimension nulle). Version supérieure refusée. Migration. |
| `project_store.gd` | Chaque action, puis annuler, restaure l'état précédent à l'identique. Refaire réapplique l'action. Les signaux sont émis. Déplacer un nœud met à jour tous les murs reliés. Supprimer un mur supprime ses ouvertures. |
| `log16.json` | Charge sans erreur. Surfaces à ±3 % du tableau de l'architecte. |

- **CI** : un workflow GitHub Actions lance les tests sur chaque PR vers `develop`, avec Godot 4.7 headless.
- Le rendu, les caméras et les interactions sont vérifiés manuellement via une checklist dans chaque PR concernée.

## 11. Découpage en jalons

Chaque jalon correspond à une branche `feat/*` et à une PR vers `develop`, et produit une application utilisable.

| # | Jalon | Livrable |
|---|---|---|
| M0 | Socle | GUT, CI, arborescence, `ProjectData` et sérialiseur avec tests. |
| M1 | Visionneuse | `log16.json` et calque. Murs avec onglets et ouvertures, sols, éclairage, caméra orbitale, masquage des murs. |
| M2 | Meubles | Catalogue de préréglages, pose avec fantôme, sélection, déplacement et rotation, collage au mur, panneau de propriétés, annuler et refaire. |
| M3 | Fichiers | Menu Fichier, sauvegarde automatique, gestion des erreurs. |
| M4 | Mesures | Cotes en direct, outil de mesure libre, caméra plan et calque. |
| M5 | Structure | Mode Structure : coins, murs, ouvertures. |
| M6 | Finitions | Import GLB, caméra à hauteur d'œil, chevauchements, thème de l'interface, rebond. |

Le critère de réussite est atteint dès **M4**. M5 et M6 complètent la v1.

## 12. Risques

| Risque | Mitigation |
|---|---|
| Première utilisation de Godot | Jalons courts, logique isolée dans `src/model` et testable sans scène. |
| Onglets de murs à angles aigus (pointes très longues) | Limiter la longueur de l'onglet à 2× l'épaisseur. Au-delà, coupe droite. Couvert par les tests. |
| Coût du CSG | Reconstruction uniquement sur `structure_changed`. Passage à `ArrayMesh` si la mesure le justifie. |
| Échec de l'extraction vectorielle du PDF | Durée limitée. Repli sur les cotes. Contrôle par les surfaces. |
| Mises à l'échelle hétérogènes des GLB importés | Mise à l'échelle uniforme dans `size`. L'utilisateur ajuste `size`. |
